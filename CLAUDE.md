# Cortes de podcast

When the user says "analisa a fila", "analisa esse vídeo <link>" or similar, run this workflow. Reply in Portuguese.

The user mostly drives the tool from `Painel.bat` (runs `painel.py`, a Windows desktop window in tkinter, no browser). Its INICIAR button (text box, one link per line) runs `cortes.py tudo <URL> [URL ...]`, one podcast after another, skipping to the next if one fails: download + transcribe, Ollama map, automatic cut pick (`candidatos`: neighbouring topics summing 8–20 min, ranked by score + YouTube peaks) and the Ollama title agent (`titular`, styled on `referencias_titulos.txt`, which the user edits). The user then ticks cuts and renders. `cortes.py escolher <ID>` redoes the pick + titles from the cached map. Rendered cuts go to the folder chosen in the window (`config.json` → `pasta_cortes`, default `saida/`).
Main button RENDERIZAR + THUMB runs `cortes.py finalizar <ID> N...`: renders and makes the thumb of the ticked cuts, skipping whatever already exists. Thumbnails (`thumbs.py`): `rostos` samples faces from the cuts and the user clicks the guest once per podcast (`saida/thumbs/<ID>_convidado.png`; the camera also shows the host). The face picker accepts 1 or 2 people (`<ID>_convidado.png`, `<ID>_convidado2.png`): 2 only when the podcast has TWO GUESTS (never the host); then one goes on each side, topic image between them, phrase centered. Composition copies the reference channels: black background, topic image in a rounded card top-left with a yellow border, the REAL guest cut out from a podcast frame of that cut (rembg `u2net_human_seg`, model in `modelos/rembg`; guest vs host told apart by colour histogram against the chosen face) big on the right, phrase bottom-left. Background images follow the DOAC logic in `referencias_cenas.txt` (turn the title's promise into ONE dramatic, clickbait scene: metaphor becomes real catastrophe, hidden threat, revelation, before/after, leaked evidence, human reaction, awe/scale, famous symbol in danger; one huge subject with a glowing accent; never a generic office scene; no text in the image). The art-director agent (`thumbs.planejar_cena`, `thumbs.py cenas <ID>`) reads title + thumb phrase + the cut's transcript and saves `{"emocao","ideia","tipo","cena"}` in each cut's `cena` field; `gerar` uses a saved `cena` if present. When the user asks in chat, write these `cena` fields yourself (English, concrete): it beats the local 7B model. `gerar` sends the scene to Google Flow (no person), sends the prompt to Google Flow (Nano Banana Pro, 1 image per cut: the bridge sets x1) through `flow_ponte.py`, which runs with the tool's own `.venv` (Playwright driving the installed Google Chrome, no browser download) and the chosen account's Chrome profile. It drives the Flow UI at flow.google.com itself ("+" → "Upload media" → photo → prompt box → "Start generation"; results are the project imgs ≥1000 px wide). The tool is standalone: `D:\AUTO THUMB\automacao-flow-copa` (never edit it) is only an optional extra source of already logged-in profiles (`thumbs.FLOW_ANTIGO`). ~80 s per cut. Then the text ("thumb" field; `*word*` = red, otherwise first half of lines red) is drawn locally with Montserrat Black, black outline, yellow border. Each podcast gets its own folder inside the output folder, named after the YouTube title (`cortes.pasta_podcast`); never mix podcasts. Rendered video and final thumb share the cut's TITLE as file name (`cortes.arquivo_final`: `<pasta do podcast>/<titulo>.mp4` / `.jpg`, with `? " : / \ * < > |` stripped), so the user knows which is which. The window's Limpar button only resets the UI (no files deleted). Everything of a podcast lives in its folder: finished cuts/thumbs at `saida/<titulo do video>/`, work files (original video, transcript, words, parts, map, `<ID>_cortes.json`, `thumbs/`) in `saida/<titulo do video>/_arquivos/` (`cortes.trabalho(vid)`, `thumbs.thumbs_de(vid)`); nothing loose in `saida/`. The window has an always-visible "Log da automação" (red = error, green = success, blue = step; also saved per day in `logs/AAAA-MM-DD.log`) and a % progress bar computed from the log (`painel.progresso`). Flow account: picked in the window ("Conta do Google Flow", saved as `config.json` → `conta_flow`). Accounts = Chrome profiles the window creates in `contas\<nome>` ("+ Nova conta"), plus, if that folder exists on the PC, `D:\AUTO THUMB\automacao-flow-copa\.auth\flow-profile-chrome-*` (`thumbs.perfis()`); Entrar/Sair open that profile's Chrome on flow.google.com / Google logout. `Login_Flow.bat` opens the chosen one. Failover: `gerar` starts with the chosen account and, if it fails (no project screen, or 2 requests in a row without image), moves to the next profile with only the missing images. Do not add features meant to dodge Google's usage limits (load spreading across accounts, quota detection to hop accounts): the user was told this risks account suspension.
When the user asks here in chat, you can still pick the cuts and write the titles yourself (hybrid mode below); that gives better results than the local 8B model.

Everything lives on drive D:. Never write to C:. Always use the venv: `.venv\Scripts\python`.

1. Prepare: `.venv\Scripts\python cortes.py preparar` (reads `fila.txt`) or `... preparar <URL>`.
   Downloads the video and writes `saida/<ID>_transcricao.txt`. Run in background: Whisper can take a while.
2. Map with Ollama (hybrid mode): `.venv\Scripts\python cortes.py analisar <ID>` (run in background; ~30 min for a 4h podcast on the GTX 1660 Super).
   Pass 1 splits each ~10 min block into parts typed conteudo/abertura/patrocinio/encerramento. Pass 2 asks yes/no at every boundary "same topic?", so a topic that crosses blocks stays whole. Both are cached in `saida/<ID>_partes.json` (delete it to redo). Output: `saida/<ID>_mapa.txt`, one line per topic with time range, duration, average score and part summaries; intro/sponsor/outro are marked. Models: `llama3.1:8b` for the map (env `CORTES_MODELO`), `qwen2.5:7b` for titles (env `CORTES_MODELO_TITULOS`). Ollama models live in `D:\Ollama\models` (user env `OLLAMA_MODELS`).
   Then YOU pick the cuts: read the map (not the whole transcript), choose the strongest topics, merge neighbouring topics the model split wrongly, split ones it lumped together, and read the transcript only around each chosen start/end to land the start on a hook and the end where the topic closes. Never include a [PATROCINIO]/[ABERTURA]/[ENCERRAMENTO] range; check the transcript for sponsor reads the map missed (e.g. "HostGator", "cupom", "link na descrição"). Write the titles yourself.
   Transcript format: lines are `[seconds] text`, one sentence group per line; `>>` marks a speaker change. The header may list YouTube "most replayed" timestamps, a strong signal.
   Word timings live in `saida/<ID>_palavras.json`. `cortar` snaps each start/end to the nearest sentence boundary (±3s) and avoids a camera-cut flicker at the edges, so `inicio` = timestamp of the line where the hook sentence starts and `fim` = timestamp of the first line AFTER the topic closes.
   Never start a cut on a word that needs earlier context: "então", "isso", "ele/ela", "aí", "e", "mas", "porque", "também", "esse/essa", "daí". The viewer must understand the first sentence on its own.
   Reference style: long YouTube podcast cut channels, 16:9 horizontal. Each cut covers ONE self-contained topic.
   - Length follows the topic: usually 8–15 min; up to ~25 min only if the topic holds attention the whole time. Never pad, never chop a topic in half.
   - Viral criteria: controversy, prediction/warning ("essas profissões vão sumir"), surprise, revelation, strong personal story, blunt opinion, humor, conflict, high-value practical advice.
   - Avoid intro, sponsor reads, outro, slow talk.
   - Start at a hook sentence and end when the topic closes, never mid-sentence. No overlap. Order from most viral to least.
   - Pick as many cuts as the podcast supports with strong topics (typically 3–8), unless the user asked for a number.
   - For each cut give: a YouTube title (quote or claim + guest name, e.g. `"SE PREPAREM PARA SAIR DESSES TRABALHOS" - Fulano`) and a short thumbnail phrase (3–6 words, ending in "...").
3. `saida/<ID>_cortes.json` format: `[{"inicio": 754, "fim": 1420, "titulo": "...", "thumb": "...", "motivo": "..."}]` (seconds).
   Show the user the list (time range, duration, title, thumb phrase, reason) and wait for approval before cutting.
4. Cut: `.venv\Scripts\python cortes.py cortar <ID>` (add `--vertical` for TikTok 9:16; add cut numbers, e.g. `cortar <ID> 6 7`, to redo only those). Then remove the processed links from `fila.txt`.
   Output: HEVC (hevc_nvenc cq 26, ~35 MB/min at 1080p60), podcast voice cleanup, 0.3s fade in/out.
